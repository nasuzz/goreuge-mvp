# 배포·제출 런북 (이슈 #9)

DRI: C. 검수: A·B.

배포부터 제출본 태그까지 순서대로 따라가는 문서다. 값은 전부 실측으로 확인한 것이며,
근거 명령을 함께 적었다. 숫자가 안 맞으면 이 문서가 아니라 실측을 믿고, 실측이 바뀌었으면
이 문서를 고친다.

## 먼저 — 대부분은 스크립트가 대신한다

`scripts/deploy.sh`(이슈 #43)가 아래 2장과 4-1장을 그대로 실행한다. 손으로 밟을 이유가
없으면 이쪽을 쓴다.

```bash
scripts/deploy.sh --check                              # 로컬 검증 + 비밀값 스캔
scripts/deploy.sh --prod --smoke                       # 배포 후 배포 URL에 스모크
scripts/deploy.sh --api-base https://<배포url> --smoke  # 이미 배포된 URL만 검증
```

`--smoke`는 기본이 `--skip-mutating`이라 데모 데이터를 건드리지 않는다. 전체 스모크가
필요하면 `--mutating-smoke`를 함께 준다.

**스크립트가 대신하지 못하는 것은 1장(Vercel 프로젝트 설정과 환경변수)과 3장(리허설),
4-2~4-4장이다.** 1장은 대시보드 작업이고 나머지는 사람이 눈으로 확인해야 한다.

## 1. Vercel 배포

### 1-1. 프로젝트 설정

`web/`이 저장소 루트가 아니므로 **Root Directory 지정이 필수**다. 루트 `package.json`은
`name: goreuge-shared` / `type: commonjs`이고 Next 앱이 아니다.

| 항목 | 값 |
|---|---|
| Root Directory | `web` |
| Framework Preset | Next.js (자동 감지) |
| Build Command | 기본값 (`next build`) |

`vercel.json`으로는 Root Directory를 지정할 수 없다. 대시보드에서 설정해야 한다.

### 1-2. 환경변수

| 키 | 값 | 비고 |
|---|---|---|
| `SUPABASE_URL` | A가 공유한 값 | |
| `SUPABASE_SECRET_KEY` | A가 공유한 값 | `NEXT_PUBLIC_` 접두사 금지 (D5-a) |
| `DEMO_USER_ID` | `a0000000-0000-4000-8000-000000000001` | **아래 경고 참고** |
| `DEMO_TODAY` | `2026-09-01` | 비우면 실제 KST 날짜를 쓴다 |
| `GEMINI_API_KEY` | B가 Google AI Studio에서 만든 값 | 서버 전용, `NEXT_PUBLIC_` 접두사 금지 |
| `GEMINI_MODEL` | `gemini-3-flash-preview` | Gemini 무료 tier 대상 모델. 필요 시 교체 |

## 2. 배포 후 검증

### 2-1. API 스모크

`scripts/deploy.sh --api-base https://<배포url> --smoke`는 아래 두 번째 `--skip-mutating`
명령과 같은 안전 모드로 실행한다. 옵션 없이 직접 돌리는 첫 번째 명령은 전체 스모크다.

```bash
API_BASE=https://<배포url> node test/api-smoke.mjs
```

0~5단계를 자동 검증한다. 실패 0건이어야 한다. 종료 코드로 성공을 판정할 수 있다
(성공 0 / 실패·중단 1).

위 명령처럼 옵션 없이 직접 돌리면 4단계가 데모 계약을 실제로 `risk`로 바꾸고 임시 유저를
남긴다. 데모 직전이라면 `--skip-mutating`으로 돌리고, 이미 돌렸다면 재시드한다.

```bash
API_BASE=https://<배포url> node test/api-smoke.mjs --skip-mutating
```

### 2-2. 재시드

스모크가 데모 데이터를 오염시켰거나 상태가 의심스러우면 Supabase SQL Editor에
`db/seed-demo.sql`을 그대로 붙여넣는다. 먼저 지우고 넣으므로 몇 번을 실행해도 같은
상태가 된다.

`db/seed-demo.sql`은 `src/shared/mock-data.json`에서 생성한 산출물이다. 직접 고치지 말고
재생성한다.

```bash
node db/seed-demo.mjs > db/seed-demo.sql
```

1:35 → 2:00으로 이어가는 것은(위 정정 이후) 문제 없다.

> **[2026-09-07 정정 → 재복원, [#40](https://github.com/hsoo23/goreuge-mvp/issues/40)]**

>
> 뺐던 근거는 "10장 P1이라 구현되지 않았다"였는데, 그 뒤 #55가 머지되어
> **입금 확인과 공제율 역산이 실제로 동작한다**(엔진 `confirmPayment`, 정산함 화면,
> `test/payment-confirm-verify.ts`). 제외 사유가 사라졌으므로 원래 자리로 되돌린다.
>
> 값은 실측이다. `contract-001`(D에이전시, 총액 2,400,000원)의 잠정 실수령액은
> 참조율 3.3%로 계산한 2,320,800원인데, 실제 입금 2,296,800원을 넣으면 공제율이
> **4.3%로 역산**되고 상태가 `completed`로 바뀐다. **참조율은 추정이었고 실제는
> 달랐다**는 것을 그 자리에서 보여주는 구간이라, 5-1의 "확인 전에는 참조율을
> 적용하지 않는다" 원칙과 짝이 맞는다.
>
> **D-day는 09-14에서 움직이지 않는다.** 2:25는 1:35(위험 전환) 이후 상태에서
> 이어지므로 이 시점 기준선은 09-30이 아니라 09-14다 — 실측으로 확인했다.
> 이미 예정일에 들어올 것으로 잡혀 있던 돈이 확정된 것뿐이라 곡선이 바뀌지 않는다.
> 숫자가 안 바뀌는 게 정상이고 대본에서도 그렇게 설명한다. 이 구간의 메시지는
> D-day 변화가 아니라 **잠정값이 실제값으로 교체되는 것**이다.
>
> (#8에서 2:00 대응안이 같은 함정에 걸린 적이 있다 — 기준 상태 숫자를 적어두고
> 위험 전환 이후에 시연해서 효과가 0일로 나왔다. 순서대로 이어서 재는 것이 중요하다.)
>
> 2:00은 25초, 2:25는 20초를 쓴다. 리허설에서 2:00이 모자라면 2:25를 먼저 줄인다.
>
> 빠진 25초만큼 **2:00 구간이 2:00~2:45의 45초를 쓴다.** 가정 두 개(선금 100만원,
> 카드 결제 2주 연기)를 카드 2장으로 나란히 놓고 각각 며칠이 회복되는지 짚는

> 앞당긴다 — 시각은 리허설 실측으로 확정한다.
>
> 6-3 표에 이 기능들이 있다고 P0인 것은 아니다. 6-3은 정산함 화면의 기능 명세이고,
> **우선순위의 출처는 10장이다.**

## 4. 제출 전 최종 점검

### 4-1. 키·개인정보 미포함

`scripts/deploy.sh --check`가 아래를 그대로 실행한다. 손으로 돌릴 이유가 없으면 그쪽을
쓴다. 여기 남겨두는 것은 스크립트가 무엇을 보는지 알기 위해서다.

**스캔 대상은 `origin/main`이 아니라 현재 작업트리다.** `vercel --prod`는 git이 아니라
로컬 디렉터리를 그대로 업로드하기 때문이다. `origin/main`만 보면 아직 커밋하지 않은
변경이나 로컬 전용 브랜치에 들어 있는 키를 "깨끗하다"고 통과시키고, 그 코드가 그대로
배포된다. (이 문서의 이전 판이 `origin/main` 기준으로 적혀 있었다. 이슈 #43·PR #44에서
스크립트를 만들며 드러난 구멍이다.)

```bash
git grep -nIE "(eyJ[A-Za-z0-9_-]{30,})|(sk-[A-Za-z0-9]{20,})|(AIza[A-Za-z0-9_-]{20,})|(sb_secret_[A-Za-z0-9_-]{10,})|(service_role)|(-----BEGIN [A-Z ]*PRIVATE KEY)" -- . ':!*.lock' ':!package-lock.json' ':!scripts/deploy.sh'
git ls-files | grep -E "\.env" | grep -v "\.env\.example$"
git log --all --diff-filter=A --name-only --format="" | sort -u | grep -E "\.env($|\.local|\.production)"
git grep -nIE "01[0-9]-[0-9]{3,4}-[0-9]{4}|[A-Za-z0-9._%+-]+@(gmail|naver|daum|kakao|hanmail)\.[a-z]{2,3}" -- . ':!*.lock' ':!package-lock.json'
```

2·3·4번은 결과가 없어야 한다. 2번은 `.env.example` 계열을 빼고 세므로, 값이 든 `.env`
파일이 트리에 들어왔을 때만 걸린다.

**1번은 손으로 돌리면 이 문서 자신의 위 블록 한 줄에 걸린다.** 정규식을 예시로 적어둔
줄이라서다. 그 한 줄 외에 다른 결과가 없으면 통과다.

```
docs/release.md:<위 블록의 git grep 줄>     <- 유일하게 허용되는 결과
```

`scripts/deploy.sh --check`는 이 한 줄만 결과에서 걸러내므로 사람이 판단할 필요가 없다.
같은 파일 전체를 빼지 않는 것은, 그러면 이 문서에 진짜 키가 들어와도 못 잡는 사각지대가
생기기 때문이다. 반면 `scripts/deploy.sh`는 정규식 자체를 코드로 담고 있어 줄 단위로
거르기 어려워 파일 전체를 뺀다 — 탐지 로직을 담은 파일이라 비밀값이 섞일 자리가 아니다.

`origin/main`을 따로 확인하고 싶으면 위 명령에 `origin/main`을 붙여 한 번 더 돌린다.
배포 안전성의 기준은 작업트리이고, 저장소 이력 점검은 그와 별개다.

휴대폰·이메일 패턴에서 UUID가 오탐으로 걸리지 않게 앞자리를 `01`로 고정했다. 범용
`[0-9]{3}-[0-9]{3,4}-[0-9]{4}`를 쓰면 `d0000000-0000-4000-8000-…` 같은 시드 UUID가
전부 걸린다.

### 4-2. 합성 데이터·세무 제한 고지

| 공휴일 보정 (#57) | 엔진 구현, 기본 OFF | 켜면 데모 숫자가 바뀐다(익월 말일 10-31 → 11-02). 끈 채로 간다 |

### 4-3. 기능명세와 구현 일치

**우선순위의 출처는 `docs/mvp-spec-v3.md` 10장이다.** 6장은 화면별 기능 명세이므로 거기
실려 있다고 P0인 것이 아니다. 10장 P0 11개가 실제로 동작하는지 화면에서 확인한다.

엔진 쪽은 `src/shared/engine-interface.md`가 선언한 함수와 `src/engine/` 구현을 대조한다.

> **[2026-09-07 갱신]** 이 절에 `confirmPayment`(3-9)와 `recalculateClientStats`(3-10)가
> 미구현이라고 적혀 있었으나, #55가 머지되어 **둘 다 구현됐다**(`src/engine/index.ts`가
> export하고 `test/payment-confirm-verify.ts`가 회귀를 고정한다). 선언된 함수가 전부
> 구현된 상태다.

거래처 지연 통계는 이제 `recalculateClientStats`로 갱신된다. 다만 **데모 숫자는 그대로다**
— 시드 데이터에 `completedCount`·중앙값·p90이 이미 들어가 있고, 데모 중에 입금 확인을
하지 않는 한(2:25 구간은 대본에서 빠져 있다) 통계가 바뀌지 않기 때문이다. 리허설에서
입금 확인을 눌러봤다면 `db/seed-demo.sql`을 재실행해 통계를 되돌린 뒤 본 촬영에 들어간다.

## 5. 머지 순서 주의

브랜치가 서로 위에 쌓여 있어 순서에 따라 내용이 유실될 수 있다.

- **#25 → #29** — #29는 #25 위에 쌓였지만 마지막 커밋을 아직 담고 있지 않다. #29를 먼저
  머지하면 그 수정이 main에 들어가지 않는다.
- **#27은 #29에 포함된다** — #29가 #27의 커밋을 이미 담고 있다. #29를 머지하면 #27은
  불필요하다. 둘 다 열어두면 같은 충돌을 두 번 해소하게 된다.
- **`web/.env.example`** — #21이 머지되면서 #27·#29가 이 파일에서 충돌 상태가 됐다.
  내용 충돌이 아니라 위치만 겹치므로, 들어오는 `OPENAI_*` 블록을 살리면 된다.
